# REVIEW.md

List every defect you found in the starter `app/main.py` (helpers and endpoints). For each one:

| # | Where (function / line) | What is wrong | How you'd notice it (test, input, or symptom) | How you fixed it |
|---|---|---|---|---|
| 1 | `compute_late_minutes` (lines 33–37) | Checked `minutes > 10` after integer floor division. Per rule R2, late threshold is strictly > 10:00 (600s) after shift start. At 10m01s (e.g. 09:40:01 for 09:30 shift), elapsed time is 601s; `int(601/60) = 10`, and `10 > 10` is False, returning 0 instead of 10. Also `start = punch_in.replace(...)` placed shift start on punch-in calendar date, failing overnight shifts after midnight. | Calling with punch-in at 09:40:01 for a 09:30 shift returned 0 late minutes instead of 10. | Compared raw elapsed seconds `(punch_in_ist - shift_start_dt).total_seconds() > 600`. If true, returned `int(diff_sec // 60)` using the shift's attendance date in IST. |
| 2 | `compute_work_hours` (lines 40–42) | Used Python's built-in `round(seconds / 3600, 2)` which performs banker's rounding (round-half-to-even) and float arithmetic rather than round-half-up. | Values with fractional parts ending in .005 or .025 (e.g. 2.125 hours) rounded down to 2.12 instead of 2.13. | Used `(Decimal(diff_seconds) / Decimal(3600)).quantize(Decimal("0.01"), rounding=ROUND_HALF_UP)` per rule R4. |
| 3 | `compute_overtime` (lines 44–48) | Returned `max(0, int((punch_out - end).total_seconds() / 60))` without checking the 30-minute threshold required by R3. Also placed `end` on `date_str` without shifting to the next day for overnight shifts (`shift_end <= shift_start`). | A punch-out 25 minutes after shift end returned 25 instead of 0. Overnight shifts (22:00–06:00) calculated incorrect or negative overtime. | Offset `shift_end` to `attendance_date + 1 day` for overnight shifts, and counted whole minutes only when `diff_seconds >= 1800` (>= 30 mins), otherwise 0. |
| 4 | `health` (lines 72–74) | Returned `{"status": "ok"}` unconditionally without checking MongoDB connectivity. Contract requires 200 only if MongoDB answers a ping, else 503. | Stopping MongoDB service still resulted in a 200 OK response from `/health`. | Executed `client.admin.command('ping')` inside a try-except block, raising `HTTPException(503, "Database unavailable")` if ping fails. |
| 5 | `create_employee` (lines 78–85) | Used check-then-insert (`if db.employees.find_one(...)`), creating a concurrency race condition where duplicate creates both succeed. Stored naive `datetime.now()` and returned it without converting to epoch milliseconds. Missing validation for `emp_code` regex, email format, and `shift_start != shift_end`. | Concurrent requests with the same `emp_code` yielded two 201s instead of one 201 and one 409; response returned datetime object/string instead of integer epoch ms. | Added unique index on `emp_code` and handled `DuplicateKeyError` returning 409. Added Pydantic field validators and serialized `created_at` as epoch milliseconds integer. |
| 6 | `list_employees` (lines 89–96) | Off-by-one pagination bug `skip = page * page_size` (skipped page 1 entirely); `total = db.employees.count_documents({})` ignored the `department` filter; omitted sort by `emp_code` ascending; returned raw datetime instead of epoch ms. | Calling `GET /employees?page=1` skipped the first 20 records; filtering by department returned the total collection count. | Fixed `skip = (page - 1) * page_size`, passed filter `q` to `count_documents(q)`, added `.sort("emp_code", 1)`, and formatted items. |
| 7 | `punch_in` (lines 100–103) | `datetime.fromtimestamp(...)` used local naive time without UTC/IST awareness; did not truncate instant to whole seconds (R1); did not calculate attendance date for overnight shifts before `shift_end` (R1); did not check employee existence (raised 500 instead of 404). | Punching in for a non-existent employee threw 500 `TypeError: 'NoneType' object is not subscriptable`; overnight shift punch-in before shift end assigned the wrong calendar day. | Checked employee exists (raising 404 if missing), truncated instant to whole seconds, converted to IST, determined correct attendance date per R1. |
| 8 | `punch_in` (lines 104–121) | Check-then-insert race condition (`if db.attendance_logs.find_one(...)`); added non-contract field `doc["id"] = str(res.inserted_id)`; returned raw BSON datetime rather than integer epoch milliseconds. | Two simultaneous punch-ins for the same employee and date both succeeded; response schema validation failed due to extraneous `id` field. | Relied on a unique compound index on `(emp_code, date)` catching `DuplicateKeyError` returning 409; removed `id` and formatted output per `AttendanceRecord`. |
| 9 | `list_attendance` (lines 144–150) | Loaded the entire collection into memory via `list(db.attendance_logs.find(q))` and sorted in Python (`docs.sort(...)`), causing memory exhaustion at 100k docs; missing secondary sort by `emp_code` ascending; injected illegal `id` field; missing validation for `date_from > date_to` (must return 422); returned BSON datetimes instead of epoch ms. | Requesting `date_from > date_to` returned 200 instead of 422; high memory usage and query timeout on 100k documents; response contained illegal `id` field. | Used database-level query `.sort([("date", -1), ("emp_code", 1)]).skip(skip).limit(page_size)`, added `date_from > date_to` check raising 422, and properly converted timestamps. |
| 10 | Startup / Lifespan (module level) | No indexes were created at startup. The seeded database only has `_id`, leading to collection scans (COLLSCAN) for all queries and allowing duplicate entries. | Explain plans showed `COLLSCAN` on attendance and employee collections; concurrent duplicate writes succeeded. | Added FastAPI lifespan context manager running `init_indexes(db)` creating all unique and compound indexes idempotently at startup. |
| 11 | `PunchInIn` validation (lines 63–67) | Allowed any string for `status` (including `ABSENT` and `LEAVE`) and accepted seconds-like integers (< 100000000000) for `punched_at`. | Supplying `status="ABSENT"` or `punched_at=1783310400` (seconds) was accepted with 201 instead of 422. | Enforced regex pattern `^(PRESENT|WFH|ON_DUTY)$` on `status` and `ge=100000000000, le=4102444800000` on `punched_at`. |

Also note anything you looked at and decided was **not** a defect, and why:

1. `load_dotenv()` at top level: We examined whether calling `load_dotenv()` violates the environment contract where real injected environment variables must take precedence over `.env`. By default in `python-dotenv`, `load_dotenv(override=False)` does not overwrite variables already present in the execution environment, so real injected environment variables always take precedence.
2. Absence of an auto-generated surrogate ID on attendance records: We checked whether attendance documents require an `id` field. Per the OpenAPI contract and `DATA_MODEL.md`, attendance records have no ID and are addressed strictly by the natural composite key `(emp_code, date)`. Stripping `_id` and omitting `id` was correct.
